 CampusFix Software Process Model and Project Plan

 1. Selected Software Process Model

For the development of CampusFix, I have selected the Incremental Software Development Model.

The Incremental Model involves developing a software system in smaller parts called increments. Each increment adds new functionality to the system until the complete system is developed.

 2. Why I Chose the Incremental Model

I chose the Incremental Model for CampusFix because the system has several different features that can be developed and tested separately.

For example, the system will need to allow users to report maintenance problems, allow maintenance staff to manage requests, and allow administrators to monitor requests. These features can be developed in separate increments.

Using the Incremental Model will allow each part of the system to be developed and tested before additional functionality is added. This can make it easier to identify problems early and make improvements as the project progresses.

The model is also suitable for a semester project because the system can start with basic functionality and gradually become more complete over the development period.

 3. Planned Increments

 Increment 1: Basic Maintenance Request Reporting

The first increment will focus on allowing students and staff to report maintenance problems.

It will include basic information such as the problem description, location, category, and date reported.

 Increment 2: Request Management

The second increment will add functionality for maintenance staff to view, update, and manage reported maintenance requests.

Requests will have statuses such as pending, assigned, in progress, and resolved.

 Increment 3: Prioritization and Assignment

The third increment will add the ability to prioritize maintenance requests and assign them to maintenance personnel.

This will help maintenance staff identify which requests require attention and who is responsible for handling them.

 Increment 4: Monitoring and Reporting

The fourth increment will add monitoring and reporting features.

Administrators will be able to view maintenance requests and monitor information such as unresolved requests, completed requests, priorities, and response times.

 4. Project Plan

Week 1
- Define the CampusFix problem.
- Identify the intended users and stakeholders.
- Write the problem statement.

Week 2
- Select and justify the Incremental Model.
- Define the planned system increments.
- Prepare the project development plan.

Week 3
- Develop the Software Requirements Specification (SRS).
- Identify functional and non-functional requirements.
- Define the main system requirements.

Week 4
- Develop the system architecture.
- Create the main use-case model.
- Begin designing the system structure.

Week 5
- Develop UML class and sequence models.
- Review the system design.
- Prepare for development of the working prototype.

 5. Expected Outcome

By following the Incremental Model, CampusFix will be developed progressively. Each increment will add useful functionality to the system while allowing the existing functionality to be tested and improved.

The final result will be a working prototype that demonstrates the main functions required for managing university maintenance requests.
